# Design

## Context

- Tiles are `TileKind` values in 64×64×1 chunks (`GameWorld`, `set_tile_cached` / `get_tile_cached`, chunk coords via `div_floor`). `ensure_chunk` generates only tiles; structures are queued in `pending_structures` and applied by `Game::ensure_chunk_with_pending_structures`, which `Game::tick` calls only for the 3×3×3 chunks around the player.
- `Game::tick` adds the action's tick cost (move ≈ 200 ticks) to `res.time.tick` and runs every system once. Combat auto-ticks advance the game while combat is active.
- Placement: `world_build.rs` Place mode puts `TileKind::from_item_kind(item)` on an adjacent tile; Break mode mines it. `BuildMode` is Movement / Break / Place, cycled by `build.TOGGLE_BREAK_PLACE_MODE`.
- The corpse-looting window (`CorpseLootingState::LootingCorpse`) already moves items between an entity's `Inventory` and the player's.

## Goals / Non-Goals

**Goals:**
- One foundation for every factory block: entity-backed state, facing, rotation, breaking, deterministic stepping.
- Factory progress depends only on elapsed game time and seed.

**Non-Goals:**
- Real-time ticking (decided: turn-based).
- Multi-tile blocks (every factory block is 1×1).
- Any specific machine beyond the chest; those are their own changes.

## Decisions

### Factory blocks are entities on a marker tile
A factory block is an ECS entity with `Position`, `FactoryBlock { kind: FactoryKind, facing: Facing }` and per-kind components (`Storage` for chests, and later `Belt`, `Machine`, `Generator`, `PowerPole`). Its tile is set to a single `TileKind::FactoryBlock` marker (impassable) so movement, worldgen and existing tile code treat the space as occupied. A spatial index `HashMap<Position, Entity>` on `Resources` gives O(1) lookup by position; it is rebuilt on load.
Alternative: a new `TileKind` per block with side tables. Rejected: per-kind state (inventories, progress) would live outside the ECS and outside the save registry.

### Facing
`Facing { North, East, South, West }` with `rotate_cw()` and `offset()`. Non-directional kinds (chest) ignore facing. Glyphs come from the kind plus facing (e.g. belts `^ > v <`).

### Rotation UI
- Before placing: `build.ROTATE_PLACEMENT` (default `r`, active only in Place mode, where `action.PICKUP_ITEMS` is not handled) cycles a `placement_facing` stored in `BuildPanelState`; the hotbar shows an arrow for it.
- After placing: `BuildMode::Rotate` is added to the toggle cycle (Movement → Break → Place → Rotate). Its direction keys reuse the `build.PLACE_*` bindings, so no new direction keys are needed.

### Factory stepping
A `FactoryClock { last_tick, carry }` resource. After the existing systems run in `Game::tick`, the factory scheduler computes `elapsed = tick - last_tick + carry`, runs `elapsed / FACTORY_STEP_TICKS` steps (`FACTORY_STEP_TICKS = 20`, five steps per game second), and keeps the remainder in `carry`. Each step runs the factory systems in a fixed order (growth, generators, power, machines, belts, as later changes add them) over all factory entities, independent of chunk loading, which gives "simulate wherever placed".

### Pass time
`action.PASS_TIME` (default `,`) runs `Game::tick` with an empty intent of cost 1000 in chunks of 100 ticks, checking for `CombatTriggered` after each chunk and stopping there (so creatures and combat behave as they do during normal play). The client then applies the tick result through `App::apply_tick_result`.

### Chunk boundaries
All factory code uses world coordinates and the spatial index, never chunk-local indices. Neighbor tiles are read through one helper, `Game::factory_tile(pos)`, which calls `ensure_chunk_with_pending_structures` for the target chunk before reading, so a chunk first touched by a machine is generated with its structures exactly as one first visited by the player. Tests compare a chunk generated via a machine against the same chunk generated by walking there with the same seed.

### Saving
New components and resources (`FactoryBlock`, `Storage`, `FactoryClock`, the placement facing) are saved. With `flawless-world-saves`, they're registered in its component registry; before it, they're added to the current save format.

## Risks / Trade-offs

- [Large factories slow every action] → Steps are cheap fixed-size loops; revisit with profiling once belts exist. Pass time runs in 100-tick chunks.
- [Machine-triggered chunk generation places structures in odd order] → Structures apply through the same pending-structure path as player visits; equality test covers it.
- [`r` in Place mode conflicts with a future binding] → All keys are configurable; documented in the help panel.

## Implementation Notes

- **No `Storage` component:** `Inventory` already has `max_slots`, so a chest is a factory block with an `Inventory { max_slots: 16 }`. `factory::move_one_item` moves single items between inventories and refuses a new stack when the target is full.
- **Saving:** `FactoryBlock` is registered in `saved_components!`; `FactoryClock` is a `Resources` field (saved automatically, `#[serde(default)]` for older saves). The position index is derived data: `#[serde(skip)]`, rebuilt from the entities on load.
- **Shared placement rule:** "passable tile, no entity" moved from the client into `factory::can_place_at`, used for plain blocks and factory blocks.
- **Sprites:** factory blocks draw through their `SpriteRef` (category `factory`) over a `TileKind::FactoryBlock` marker tile. `FactoryKind::sprite(facing)` is where directional kinds (belts) will pick per-facing sprites.
- **Factory systems:** `factory::run_due_steps` runs after the other systems and only counts steps (`FactoryClock.steps`) until later changes add systems; the elapsed-time test compares the whole clock instead of a counter block.
- **Directional test block:** `FactoryKind::TestArrow` exists only under `cfg(test)` or the core `test-support` feature (client tests now enable it), since the chest is the only real kind and isn't directional.
- **Pass time** waits in ten 100-tick steps (a zero-distance move with a 100-tick cost, like the wait key) and stops after the step in which combat starts.
- **Chest window:** the corpse-looting window shows "Chest" titles and moves items both ways when the entity is a factory block; corpses still only give items.
